# UI guidelines

## Направление

Интерфейс должен быть минималистичным, спокойным и понятным без отдельного
обучения. Главный акцент — данные аукциона и доступное пользователю действие.

Основные принципы:

- минимум декоративных элементов;
- нейтральные цвета без ярких заливок;
- высокая читаемость чисел, дат и статусов;
- единообразное расположение действий;
- понятные loading, empty, error и disabled states;
- адаптивность без потери важных данных;
- анимации только там, где они объясняют изменение состояния.

## Цвета

Предварительная светлая палитра:

| Назначение | Цвет |
| --- | --- |
| Фон страницы | `#F6F7F9` |
| Поверхность карточки | `#FFFFFF` |
| Основной текст | `#1F2933` |
| Вторичный текст | `#667085` |
| Граница | `#E2E6EA` |
| Основной акцент | `#355C7D` |
| Акцент при наведении | `#294A67` |
| Success | `#477A5B` |
| Warning | `#9A6A2F` |
| Error | `#A64B4B` |

Цвет не должен быть единственным способом передать состояние. Статусы
дополняются текстом и при необходимости иконкой.

Палитра объявляется в Tailwind через `@theme`:

```css
@theme {
  --color-canvas: #f6f7f9;
  --color-surface: #ffffff;
  --color-ink: #1f2933;
  --color-muted: #667085;
  --color-line: #e2e6ea;
  --color-brand: #355c7d;
  --color-brand-hover: #294a67;
  --color-success: #477a5b;
  --color-warning: #9a6a2f;
  --color-danger: #a64b4b;
}
```

Каждый токен одновременно доступен как CSS variable и создаёт Tailwind
utilities. Например:

```tsx
<button className="bg-brand text-surface hover:bg-brand-hover">
  Сделать ставку
</button>
```

## Типографика

- основной шрифт — локальный Inter с системным fallback;
- основной размер текста — `16px`;
- вспомогательный текст — не меньше `14px`;
- высота строки основного текста — около `1.5`;
- числовые значения цены визуально отделяются от подписей;
- длинные названия и адреса переносятся, а не обрезаются без объяснения.

Inter хранится локально в форматe WOFF2. Подключены начертания `400`, `500`,
`600`, `700` и `900` с `font-display: swap`. Системный fallback сохраняет
читаемость во время загрузки шрифта.

## Сетка и размеры

- максимальная ширина основного контента — около `1200px`;
- поля страницы: `16px` на mobile, `24px` на tablet, `32px` на desktop;
- базовый шаг отступов — `4px`;
- основные отступы строятся из значений `4`, `8`, `12`, `16`, `24`, `32`;
- радиус карточек и контролов — умеренный, около `8-12px`;
- минимальная высота интерактивной области — `44px`.

## Компоненты

### Карточка аукциона

- номер заявки и статус находятся в верхней части;
- маршрут — главный визуальный блок;
- груз, даты и цены сгруппированы, а не показаны сплошным текстом;
- primary action всегда находится в предсказуемом месте;
- на mobile карточка перестраивается в одну колонку;
- скрытые данные объясняются текстом, а не пустым местом.

### Фильтры

- на desktop отображаются в компактной панели;
- на mobile открываются в drawer;
- активные фильтры видны без открытия drawer;
- есть явное действие «Сбросить»;
- применение фильтра не должно неожиданно прокручивать страницу.

### Формы

- label всегда видим и не заменяется placeholder;
- ошибка располагается рядом с полем;
- кнопка отправки показывает pending-состояние;
- серверная ошибка `422` связывается с полем цены, если это возможно;
- недоступная форма объясняет причину.

### Состояния данных

- skeleton повторяет геометрию будущего контента;
- empty state объясняет, почему данных нет, и предлагает следующее действие;
- error state содержит понятное сообщение и кнопку повтора;
- disabled state остаётся читаемым и имеет объяснение.

## Анимации

Используются короткие и ненавязчивые transitions:

- hover/focus кнопок и карточек — `120-160ms`;
- появление toast — `180-220ms`;
- открытие mobile drawer — `200-240ms`;
- смена skeleton на данные — мягкий fade;
- нажатие кнопки не должно вызывать заметное смещение layout.

Не используем:

- постоянные декоративные анимации;
- параллакс;
- резкие масштабирования;
- анимации, задерживающие доступ к данным.

Обязательно учитываем:

```css
@media (prefers-reduced-motion: reduce) {
  /* Отключаем необязательные движения и сокращаем transitions. */
}
```

## Доступность

- все действия доступны с клавиатуры;
- focus-visible хорошо заметен;
- контраст текста и контролов соответствует WCAG AA;
- иконки не заменяют текст там, где смысл может быть неоднозначен;
- toast не является единственным местом с критически важной информацией;
- поля формы имеют связанные `label`, description и error;
- skeleton и декоративные элементы скрыты от screen reader;
- pending-состояния передаются через `aria-busy` или понятный текст.

## CSS-подход

Используем Tailwind CSS:

- цвета, шрифты и тени объявляются как theme variables;
- layout и стили компонентов собираются utility-классами;
- базовый reset и глобальные правила доступности находятся в
  `src/styles/base.css`;
- шрифты подключаются в `src/styles/fonts.css`;
- Tailwind-токены находятся в `src/styles/theme.css`;
- `src/styles/index.css` остаётся единой точкой подключения стилей;
- повторяющиеся UI-паттерны выносятся в React-компоненты;
- произвольные значения используются только в исключительных случаях;
- CSS-in-JS не используется.

Во Vue запись выглядела бы как `class="bg-brand text-surface"`. В JSX
единственная разница — атрибут называется
`className="bg-brand text-surface"`.

## Критерий готовности

Экран считается визуально готовым, если:

- основные действия понятны без инструкции;
- нет горизонтального скролла на mobile;
- данные не прыгают при загрузке;
- интерфейс работает с клавиатуры;
- состояния различимы без опоры только на цвет;
- анимации не мешают и отключаются через `prefers-reduced-motion`.
