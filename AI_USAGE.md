# Использование AI

Документ ведётся в процессе разработки и будет обновляться после каждого
значимого этапа.

AI используется как помощник для изучения React, разбора требований,
проектирования, реализации и проверки. Ответственность за принятые решения,
понимание кода и финальный результат остаётся у кандидата.

## Как использовался AI

### Подготовка проекта

AI помог:

- создать базовый проект на React, TypeScript и Vite;
- подключить проект к GitHub;
- настроить линтер и production-сборку;
- проверить установленные зависимости;
- подключить Tailwind CSS через официальный Vite-плагин;
- организовать глобальные стили и локальные шрифты Inter;
- очистить демонстрационные файлы Vite;
- подготовить начальную структуру Feature-Sliced Design.

### Разбор задания

AI помог:

- извлечь и проверить требования из PDF;
- разбить работу на последовательные этапы;
- составить чек-листы для списка аукционов, деталей, ставок и проверки;
- обнаружить обязательное правило именования React-компонентов
  `*.component.tsx`;
- зафиксировать план разработки в README.

### Разбор OpenAPI

AI помог:

- проверить валидность `openapi.auctions.v0.json`;
- найти четыре требуемые API-операции;
- изучить DTO, enum, nullable-поля и форматы ошибок;
- сопоставить UI-фильтры с полями API;
- определить предварительные маршруты и query keys;
- выявить неоднозначности контракта;
- подготовить `docs/api-contract.md`.

### UI и стили

AI помог:

- формализовать минималистичное UI-направление;
- предложить нейтральную палитру и дизайн-токены;
- добавить базовые правила доступности;
- добавить поддержку `prefers-reduced-motion`;
- подключить начертания Inter через `@font-face`;
- оформить Tailwind theme variables.

## Решения, принятые кандидатом

Кандидат самостоятельно выбрал:

- React + TypeScript + Vite как основу проекта в рамках обязательного стека;
- минималистичный и user-friendly визуальный стиль;
- спокойную палитру без ярких цветов;
- небольшие функциональные анимации;
- Tailwind CSS как основной способ стилизации;
- хранение цветов в централизованных Tailwind theme variables;
- локальный шрифт Inter;
- публикацию OpenAPI-схемы и рабочей документации в GitHub;
- постепенный учебный темп с объяснением React через сравнение с Vue;
- постепенное создание FSD-слоёв только вместе с реальным кодом.

## Предложения AI, которые были отклонены или изменены

### Обычный CSS вместо Tailwind

Сначала AI предложил использовать обычный CSS и дизайн-токены через CSS custom
properties, чтобы уменьшить количество инструментов на старте.

Кандидат предпочёл Tailwind CSS, потому что уже уверенно с ним работает. Решение
было изменено: Tailwind подключён официальным Vite-плагином, а токены объявлены
через `@theme`.

### Системный шрифт

Сначала AI предложил системный font stack без загрузки дополнительных файлов.

Кандидат добавил локальный Inter. Решение было изменено: подключены пять
начертаний WOFF2 с системным fallback и `font-display: swap`.

## Что проверялось особенно внимательно

- соответствие endpoints и DTO исходной OpenAPI-схеме;
- различие между optional и nullable;
- enum-значения и наличие `Unknown`;
- отсутствие схемы успешного response для установки ставки;
- дублирование `hide_bets_history` в detail response;
- разные типы числовых значений в DTO;
- обязательный суффикс файлов React-компонентов;
- сохранение пользовательских файлов при перемещении шрифтов;
- попадание всех WOFF2-файлов в production-сборку;
- прохождение линтера и production build после структурных изменений;
- отсутствие npm-уязвимостей на текущем этапе.

## Известные риски

- реального backend нет, поэтому поведение будет проверяться на MSW;
- в OpenAPI у многих полей отсутствует `required`;
- некоторые примеры содержат `null` без `nullable: true`;
- успешный response установки ставки не имеет описанного тела;
- точное поведение `min`, `max` и `step` придётся формализовать в моках;
- пока отсутствуют автоматические тесты;
- пока не проверена работа будущих экранов с клавиатурой и screen reader;
- UI ещё не проверен на реальных mobile viewport;
- структура FSD пока минимальна и будет расширяться вместе с функциональностью.

## Что улучшить при наличии ещё одного дня

Раздел будет уточняться ближе к завершению проекта. Предварительно:

- расширить набор unit- и integration-тестов;
- добавить больше MSW edge cases;
- провести дополнительный accessibility-аудит;
- проверить больше размеров экранов и длинных текстовых значений;
- оптимизировать загрузку шрифтов и оставить только используемые начертания;
- провести финальный независимый code review.
